No RUN line, no other call, no other CHECK line and no expected-diagnostic text changed.

Why these values: GAP9 GCC accepts `__builtin_pulp_clip(X, Min, Max)` only with Min = -2^(N-1) and Max = 2^(N-1)-1. `(-4, 15)` breaks that rule (GCC: "expects Min and Max cst, Min=-2^(N-1), Max=2^(N-1)-1", `logs/20-F011.gcc-probes.log`). The nearest valid call keeps Max = 15 and sets Min = -16 (N = 5). Keeping Max keeps the machine instruction the same, because `p.clip` encodes only N and the backend derives N from Max. The first argument, -10, is unchanged.

The other clip, clipu and bextract[u] calls in both files (`clipu(20, 0, 15)`, `bextract(-0xFE00, 8, 8)`, `bextractu(0xFE00, 8, 8)`) are valid under the new rules and were not touched.
