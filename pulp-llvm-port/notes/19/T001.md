## Why this is equivalent

CSR addresses (1984), immediate masks (1), CSR effects, FREP instructions and the entire remaining instruction sequence are identical. The destination encoding changes, so this is classified semantic under rule 3 and covered by the explicit owner exception in owner-test-exceptions.md. The original test has only five CSR checks for six emitted operations. Exactly those five expectations are updated from LLVM updater output; all other test text is byte-identical. No production code changes.

## What breaks if this is wrong

An incorrect CSR address, mask or operation would enable/disable the wrong SSR state. Preserved FileCheck checks constrain these operands and FREP arithmetic/order. Actual worker-source lit PASS runs all four original optimization variants with integration llc; see logs/19-T001.verify.log. Saved no-dead.s and actual.s match exactly after normalizing the six approved destination/alias changes. The final emitted CSR operation had no original check; no new coverage is claimed.
