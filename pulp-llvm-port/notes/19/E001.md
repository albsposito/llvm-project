# 19/E001: tell TableGen that the `#pragma frep` option is an identifier, not a string

## What upstream changed

Upstream commit `2d0137dd6401` "[clang] Differentiate between identifier and string EnumArgument (#68550)" added a new required parameter, `bit is_string`, as the third argument of the `EnumArgument` class in `clang/include/clang/Basic/Attr.td`. It tells clang whether the attribute's enum value is written as a quoted string (`"foo"`) or a bare word (`foo`). Every existing use had to pass the new flag, so the fork's `Frep` attribute, still written with the old argument order, made clang-tblgen read its list of values (`["infer"]`) where it expected the new bit and stop with "Encountered a list when expecting a bit".

## Why this is equivalent

Before: `EnumArgument<"Option", "OptionType", ["infer"], ["Infer"]>`. Now: the same, with `/*is_string=*/false` inserted as third argument. The attribute keeps one option, `infer`, mapped to the C++ enumerator `FrepAttr::Infer`; the generated class, its members and the enum are unchanged. `false` is the right value because `#pragma frep infer` writes `infer` as a bare identifier (the fork's `PragmaFrepHandler::HandlePragma` in `clang/lib/Parse/ParsePragma.cpp` rejects anything that is not an identifier token), and because the flag only affects the generic `__attribute__((...))` argument parser, which a pragma-only attribute never goes through. This is exactly what upstream chose, in the same commit, for its own pragma-spelled attribute `LoopHint` (`#pragma clang loop vectorize(...)`), whose `Option` and `State` enum arguments got `/*is_string=*/false`: `clang/include/clang/Basic/Attr.td:4135` at `llvmorg-19.1.7`. (CORE-V `XCV*` has no clang attribute, so LoopHint is the closest reference.)

## What breaks if this is wrong

If the flag were wrong nothing about `#pragma frep` parsing would change (the pragma has its own handler), but the attribute would be advertised as taking a string literal to the generic attribute parser. If the fix were missing entirely, clang-tblgen fails and clang does not build at all. No lit test covers the pragma or the attribute: nothing under `clang/test` contains `#pragma frep`, and the fork's frep tests (`llvm/test/CodeGen/RISCV/freploop.ll`, `freploop-nested.ll`, `llvm/test/MC/RISCV/rv32xfrep-valid.s`) start from IR or assembly, so they never reach this code. The only check is by hand, once clang builds: compile a small C loop preceded by `#pragma frep infer` with `clang --target=riscv32 -S -emit-llvm`. The output should contain a call to `@llvm.riscv.frep.infer()` in front of the loop, which `CodeGenFunction::addFrepMetadata` in `clang/lib/CodeGen/CGStmt.cpp` emits when the option is `FrepAttr::Infer`. `-Xclang -ast-dump` should show the `FrepAttr` with option `Infer` on the loop statement.
