# 19/T005: extension-help expectation needs a scoped test-policy exception

## What upstream changed

`207e45fb67ee3dbec9590d9303eebf4f720c8a40` "[RISCV] Add back SiFive's cdiscard.d.l1, cflush.d.l1, and cease instructions. (#83896)" increases extension-help column width from 20 to 21. The fork's 26 carried expectation rows retain the old padding. Separately, `80628ee0d555` "[RISCV] Generate RISCVISAInfo table from RISCVFeatures.td. (#89955)" makes the 21 smallfloat extensions absent until approved task E004 lands.

## Why this is equivalent

The owner approved the formatting-only proposal in `notes/19/owner-test-exceptions.md`. The conductor authorized narrowing it to 25 spaces after actual verification showed the longest name (`xfexpauxvecaltquarter`, 21 characters) already matches width 21 and needs no padding. Applied one ASCII space before the version on the other 25 rows. Names, versions, order, inputs and assertions are unchanged. `T005.corrected.patch` supersedes the mistaken 26-space proposal; it leaves the longest-name row untouched. No LLVM updater supports this raw string; this is the approved narrow formatting exception.

The branch first cherry-picks approved E004 commit `c29a8b4cc12210a181ad26af5b25e104799cc348` as dependency `fa4f10654ef5`, unchanged. It restores 21 smallfloat registration rows; T005 itself only adjusts padding. These are separate commits in separate owning clusters, and neither alone fixes the entire unit failure.

## What breaks if this is wrong

`RiscvExtensionsHelp.CheckExtensions` fails if extension names, versions or column padding differ. The own-worktree baseline build succeeded, and its exact GoogleTest filter reproduced the failure (`logs/19-T005.repro.log`, exit 1). After both commits the exact filter still fails and the full suite had one failure. A standalone printer linked to the rebuilt own-worktree libraries proves the only remaining difference: `xfexpauxvecaltquarter` is 21 characters, so `left_justify(Name, 21)` emits no separator. That row was already correct before the approved patch; only the other 25 rows need one space. See `logs/19-T005.approved.output.diff`. The exact 26-space proposal was mistaken. The conductor authorized omitting that incorrect insertion; production formatting remains unchanged. Final corrected rebuild succeeds, the exact filter passes (1/1), and the full TargetParserTests suite succeeds (531 passed, 4 platform-specific host tests skipped by upstream, 535 total). Policy check: zero failures, one expected test-edit review warning. This is a unit test, so the actual GoogleTest binary is used rather than llvm-lit.
