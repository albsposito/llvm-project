# 19/T004: RISC-V missing-extension diagnostic changed upstream

## What upstream changed

Commit `13b653ab112736b92cd7f8ef249ced2b148ee7f4` ([clang][RISCV] Enable RVV with function attribute __attribute__((target("arch=+v"))) (#83674)) removed the generic feature-presence loop from Sema::CheckRISCVBuiltinFunctionCall. The loop used global target features and prevented per-function target attributes from enabling instructions. CodeGen now reports the missing feature using its generic diagnostic.

## Why this is equivalent

Updated exactly 91 expected-error annotation bodies using the owner-approved mechanical mapping in T004.diagnostic-proposal.json. All calls, arguments, RUN lines and source-line associations remain identical. Each expectation now names the exact builtin and xpulpv feature. Owner authorization in owner-test-exceptions.md supersedes the updater-only restriction for this task. Upstream's riscv64-zbkb-error.c makes the same diagnostic migration.


## What breaks if this is wrong

If feature gating were absent these builtins could emit unsupported instructions without diagnostics. The saved lit output instead shows 91 expected old messages absent and 91 replacement messages present. Updating annotations must retain each call and its exact feature requirement. Reproduction used the existing integration clang built at the task base, including a direct run against the identical isolated-worktree test; no worker compiler build was necessary for this diagnosis.
