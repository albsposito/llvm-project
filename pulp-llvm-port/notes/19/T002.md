# 19/T002: update objdump encoding display for LLVM 19

## What upstream changed

Commit b27f86b40b20942c0e809128214b43d6edde365a, [RISCV] Add an instruction PrettyPrinter to llvm-objdump (#90093), prints four-byte instruction encodings as big-endian hexadecimal words rather than space-separated little-endian bytes. All four failures reproduce in logs/19-T002.repro.log with the unchanged integration build.

## Why this is equivalent

All 18 CHECK-DISASM encoding fields now use the LLVM 19 hexadecimal word format. Reversing each prior four-byte display preserves the exact 32-bit encoding; all mnemonic/operand text, check count/order, assembly inputs, RUN lines and other checks are byte-identical. Owner approval in notes/19/owner-test-exceptions.md permits this exact mechanical transformation despite the absent LLVM 19 MC updater. The script and per-check classification are recorded in notes/19/T002.regen.md.

The retry reproduced all four failures on worker test paths (logs/19-T002.retry-repro.log). After applying the change all four actual lit tests pass with integrated tools (logs/19-T002.verify.log and .json), without rebuilding unchanged production sources. The prior read-only assembly/disassembly equivalence evidence remains in logs/19-T002.equivalence.json.

## What breaks if this is wrong

The four named MC tests continue failing. An incorrect transformation could hide a changed encoding, but the explicit read-only comparison verifies the exact 32-bit encoding and full instruction operands for every proposed replacement.
