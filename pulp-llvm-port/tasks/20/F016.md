## The problem

Backlog B87 (P1): two PULP builtins that GAP9 GCC provides are missing from our clang, and together they block 398 of the 408 SDK files that fail to compile (SDK compile parity 33.9% -> 77.1% once both exist). Survey: benchmarks/sdk-compile-survey/report.md, builtins.json, results.json; `run.py` there reproduces it.

1. `__builtin_pulp_event_unit_read_fenced` (p.elw, event-unit load that sleeps the core until the event unit answers; wrapper `evt_read32` in the PMSIS headers).
2. `__builtin_pulp_OffsetedWritePtr` (p.sw of a pointer value at base+offset; wrapper `GAP_WRITE_PTR`).

Both are used from `static inline` functions in PMSIS headers included by almost every PMSIS translation unit (3 and 10 call sites). Find their exact signatures and semantics from public sources only: the SDK headers under /home/ubuntu/gap_sdk_release (grep the wrappers and the builtin names), what GAP9 GCC accepts and emits for them (/home/ubuntu/gap_riscv_toolchain_ubuntu/bin/riscv32-unknown-elf-gcc -march=rv32imcxgap9 -mPE=8 -mFC=1 -O2 -S; compare its assembly and diagnostics), GVSoC's p.elw model (gvsoc2/core/models/cpu/iss, isa pulp_v2 / event unit), and the fork's existing sibling builtins (e.g. `__builtin_pulp_OffsetedRead`, `OffsetedWrite`, `read_then_spr_bit_*`, any existing p.elw/`event_unit_read` builtin or intrinsic) — follow exactly how the fork already defines, checks (Sema), lowers (clang codegen) and selects (intrinsic + ISel pattern) those siblings. Upstream reference style: CORE-V builtins/intrinsics in llvmorg-20.1.8 (clang/include/clang/Basic/BuiltinsRISCVXCV.td, RISCVInstrInfoXCV.td). Important semantics to get right and to state in the note: p.elw must be a volatile/side-effecting memory read that is never removed, merged, hoisted or reordered across other memory operations (it is a synchronisation point — "fenced"); check what GCC's version guarantees (asm volatile? memory clobber?) and match it.
