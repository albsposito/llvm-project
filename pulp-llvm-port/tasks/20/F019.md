## The problem

Backlog B92: GCC's `__builtin_shuffle` is unsupported by clang. The GAP9 SDK uses it 1232 times in 28 files (f16 MatMul/FFT, CNN kernels; list in benchmarks/sdk-compile-survey/results.json / report.md), mostly on the packed 2x16-bit and 4x8-bit vector types. GCC semantics: `__builtin_shuffle(v, mask)` and `__builtin_shuffle(v1, v2, mask)`, where mask is an integer vector that may be a run-time value (indices taken modulo the element count / 2x count). Clang only has `__builtin_shufflevector` (constant indices) and `__builtin_convertvector`.

First classify the SDK uses: how many have a constant mask (these could become `__builtin_shufflevector`), how many a run-time mask, which vector types. Check what GAP9 GCC emits (pv.shuffle2.h / pv.shuffle.b / pv.pack etc. — compare its assembly) and what the fork's ISel already supports for shufflevector and for the PULP shuffle intrinsics (look for existing `__builtin_pulp_shuffle*` builtins / intrinsics / patterns). Then implement `__builtin_shuffle` in clang with GCC's semantics, in the most contained way: constant masks lower to a normal `shufflevector` IR; run-time masks lower to the PULP shuffle intrinsics when the target has Xpulpv2 and the type matches (and to a generic element-extract sequence or a clear error otherwise — state which and why). Adding a new generic clang builtin touches upstream files (Builtins.td, SemaChecking.cpp, CGBuiltin.cpp): use Upstream-File-Edit trailers and keep hunks minimal, or find a fork-owned path (e.g. a RISC-V/PULP target builtin with the same name) — explain the choice in the note. Verify on GVSoC with the SDK's own shuffle-using kernels where the survey's other blockers allow, otherwise with small kernels of each mask/type shape against GCC results (constant and run-time masks, out-of-range indices).
